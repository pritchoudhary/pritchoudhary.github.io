Where it helps / where to avoid it

Use arrival steering for docking robots, NPC destinations and smooth movement toward waypoints. Avoid it for guaranteed stopping distances, vehicle tire dynamics or collision-constrained navigation. A large slowing radius can eliminate overshoot while making arrival unnecessarily slow.

The shared idea

Choose a desired velocity, turn the difference from current velocity into acceleration, cap that acceleration, then integrate motion. Arrival reduces desired speed near the goal. Avoidance changes the aim point after a local look-ahead trigger. Pursuit estimates a future aim point from target velocity.

Unity mapping

Open Assets/Scenes/SteeringLab.unity or use Tools → Engineering Lab → Open Steering Behaviors. The matching C# model uses horizontal X/Z motion. It computes a deterministic teaching trajectory, independent of PhysX or NavMesh. A production controller needs collision handling, navigation, animation and agent-specific motion limits.

Steering passed ten grouped native model checks and thirteen scripted Play checks in Unity 6000.5.2f1. Hardware input, PhysX/NavMesh integration and exported player builds remain unverified.

Repeat the experiment and inspect its limits

Integration uses a fixed 1/120 s step, with desired velocity corrected over a 0.25 s response time. The model caps acceleration before applying a speed limit. Docking/avoidance runs stop after 12 seconds; pursuit after 8. Terminal poses hold for manual inspection. Swept circle checks find first contact between frames.

The obstacle centre is (8, 0) m with radius 1.3 m; robot radius is 0.3 m. A local detection switches to the fixed bypass marker (10, 2.8) m, retaining it until X reaches 10 m. This deliberately bounded rule exposes late detection and acceleration limits without claiming general route planning. The courier begins at (6, 3) m and moves at 1.2 m/s along the second axis. Prediction is capped by both the selected horizon and distance / speed.

Repeat the named presets, inspect terminal frames, then run the stress case and Reset. Tests compare C#-executed runs, halve the timestep and sweep all exposed parameter corners.
